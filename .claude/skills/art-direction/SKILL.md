# Art brief

## Project

- Game: Item Liquid Teleport, a Mindustry JS mod (Chrono blocks, Outpost family, Yuri units). Content lives in `scripts/`, sprites in `sprites/`, strings in `bundles/`.
- Look: own Chrono style (time and purple theme) on top of vanilla Mindustry rules for pixel scale, outline and top-down read. Palette source: `sprites/spiriting/color-palette.psd`.
- Reference bar: vanilla Mindustry blocks and units. Desktop jar with the vanilla atlas: `~/Library/Application Support/Steam/steamapps/common/Mindustry/Mindustry.app/Contents/Resources/desktop.jar` (`sprites/` pages inside). Extra vanilla cuts: `tools/vanilla-ref/`.
- Reference games for UI screens: none (no new UI screens, see Pillars).
- Platform: desktop only, mouse and keys.

## Pillars

- Chrono blocks are cheat-grade by design. Never flag power level or balance. (owner, director-setup 2026-10-27)
- The Outpost family stays vanilla-balanced. Its look must read as vanilla tier, not as cheat Chrono. (owner, director-setup 2026-10-27)
- No new UI screens: UI uses vanilla Mindustry dialogs and tables only. (owner, director-setup 2026-10-27)
- Every block and unit is usable in the campaign on every planet (`CLAUDE.md`). Art must read on Serpulo and Erekir floors.

## Lenses

- Readability: each block reads at default zoom as its job (unloader, pusher, tiler, mender, build tower, booster). Chrono family members must differ by silhouette or top glyph, not only by tint. Check `sprites/blocks/<category>/` side by side.
- Identity and style: Chrono blocks share one frame and accent; Outposts share the vanilla drone-base look. Mega and Quad Outpost must read as merges of 4 parts (`tools/vanilla-ref/mega*.png`, `quad*.png`).
- Color and palette: colors come from `color-palette.psd`. Team color areas stay where vanilla puts them.
- VFX: drawn in code (`Draw`, `Lines`, `Fill`, `lib.newEffect` in `scripts/lib.js:543`), per block in `scripts/chrono-*.js`, `hypno-yuri.js`, `outpost.js`. Judge colors and sizes from code values.
- Icons: status icons `sprites/statuses/*.png`; block icons come from the block sprite. `icon.png` is the mod icon.
- Motion and poses: Yuri legs (`sprites/units/yuri*-leg.png`), drone cells; generated by `tools/gen-yuri-mech-sprites.py`, `gen-yuri-sprites.py`.
- Budget: sprites are 32 px per tile (1x1 = 32x32, 2x2 = 64x64, 3x3 = 96x96). Vanilla block sprites are RGBA with a dark outline; flag RGB files with no alpha.

## Evidence

- Sprites and code only. No in-game frames: never ask for a running game or a capture.
- Read sprite PNGs directly. Compare with vanilla sprites from the desktop jar: `unzip -l "<desktop.jar>" 'sprites/*'`, extract to the scratchpad, never into the repo.
- Upscale for comparison only with nearest-neighbor, and also judge at 1x; a player sees blocks at about 1x to 2x on desktop.
- Reference image folder (`director-review` §References): `tools/vanilla-ref/`.
- When a judgment needs a real frame, write a `LOOK` line for the owner with what to capture.

## Gates

- `file sprites/**/*.png` (size and alpha per sprite).
- `node tools/check-campaign.js` (every block is buildable; a sprite must exist for each).

## Crew

- `game-feel-director` for VFX timing and motion feel.
- No `ui-director`, `three-d-artist` or `animator` in this repo.

## Routing

| Finding | Owner |
| --- | --- |
| Sprite pixels, palette, outline | main loop: edit `sprites/` or the `tools/gen-*-sprites.py` that makes it |
| Code-drawn VFX color or size | main loop: the block script in `scripts/` |
| VFX timing, shake, motion feel | `game-feel-director` |
| Block names and descriptions | main loop + `localization` skill |

## Writes

`references/lessons.md`, `references/sources.md`. The ledger `.claude/art-ledger.md` is the main loop's.

## Never

- Never edit `sprites/`, `scripts/`, `bundles/`, `mod.hjson` or `tools/`.
- Never run `git commit`, `git push`, `tools/harness/run.sh` or the sprite generators.
- Never extract the desktop jar into the repo.
